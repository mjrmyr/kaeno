Kaeno: durable work, optional definitions

Implemented architecture · directory sources · all-to-all delegation

One native pi-durable runtime. Core owns reliable conversation and work orchestration. Optional modules decide which participants exist, what they know, and where they run.

Updated to the confirmed home/project directory scheme. This deck describes current interfaces, not the earlier speculative package registry.

Derive the design from first principles

Separate knowledge, execution and authority

Skills teach. Tool selections expose installed operations. An effect still needs its own authorization and origin fence.

Persist effective state

Freeze the native setup, selected tools and skill bindings when admitting work. A child never rereads a mutable catalog.

Data across the boundary

Core stores versioned extension-owned binding data, not callbacks that write an extension’s private records during admission.

Optionality must compile

Consumer-owned participant/environment ports and dependency checks keep agent, skill and Docker implementations out of the core import graph.

Fit with the existing primitives

Existing Decision Reason
pi-durable configure / AgentDoc Resolved ConversationSetup Use the native model, prompt and tool selection rather than inventing another agent runtime.
Tasks, Tx, ownership, receipts Keep native WORK supervision and parent/child effects One admission transaction, existing replay/cancellation behavior.
WorkBlueprint / Template Replace with a source-independent WorkPlan No agent, skill, image or JSON-template schema in core.
Native sections and tools Skill section + read_skill No alternate tool registry. Binding owners are installed native extensions.
Architecture checker Core cannot import/re-export optional modules The boundary fails the build instead of depending on contributor memory.

<startup-cwd>/.agents/agents/<dir>/agent.md

Capture cwd once. Home is an external directory source, not a global executable plugin scan. Catalog IDs retain aliases: home:coder, local:coder, kaeno-home:guide. Same-name catalog entries coexist; ambiguous short names fail.

Agent files: metadata first

---
name: reviewer
description: Review changes and report actionable findings.
model: openrouter/openai/gpt-6.1-sol
skills: [home:verification]
tools: [read, read_skill]
---
Review the supplied change carefully and explain concrete risks.

Only name and description are mandatory. Model may inherit a host default. Omitted tools inherit approved defaults; an explicit empty list remains empty. Unknown metadata is inert. No delegates field: a worker with start_work may choose anyone in its frozen plan, bounded by depth and capacity.

Admission and recovery

  1. Directory sources read bounded manifests at startup; parsers report invalid packages.
  2. Root start_work prepares and validates an in-memory plan outside Tx.
  3. Inside Tx: recheck the request key, origin fence and capacity; persist the task and plan. An already committed launch wins on replay.
  4. A child selects only from the saved participant map. All-to-all means no hand-maintained edge lists.
  5. Core configures native settings and bindings; the environment is ensured idempotently outside admission.
  6. Paused recovery checks saved native definitions, selected worker tools, binding owners and binding versions before idle refresh or scheduling.

Shrinking the approved tool surface fails preflight. It never silently filters a saved participant.

Interface: conversation setup

export interface Binding {
  readonly owner: string;
  readonly version: number;
  readonly value: JsonValue;
}

/**
 * Everything one conversation runs with, already resolved. The same shape serves the CHAT
 * assistant and every WORK participant; where it came from (Markdown, code, …) is not core's concern.
 */
export interface ConversationSetup {
  readonly model: ModelRef;
  readonly thinkingLevel?: ModelThinkingLevel;
  readonly instructions: string;
  /** Exact tool names this conversation may call; omitted means none. */
  readonly tools?: readonly string[];
  readonly bindings?: readonly Binding[];
}

Tool owners and binding owners derive the selected native extensions. Installed code does not implicitly expose its tools. The same binding reader works for CHAT and WORK; no separate work-context lookup or transaction callback is needed.

Interface: who may participate

export interface ParticipantPlan {
  readonly id: string;
  readonly description: string;
  readonly setup: ConversationSetup;
}

/**
 * Participants frozen when CHAT admits a root WORK. Every participant may delegate to every
 * other one; children always start from this saved plan, never from a live catalog.
 */
export interface WorkPlan {
  readonly root: string;
  readonly participants: Readonly<Record<string, ParticipantPlan>>;
}

export interface ParticipantSummary {
  readonly id: string;
  readonly description: string;
  /** False when the definition is discoverable but cannot run, for example without a model. */
  readonly available: boolean;
  readonly reason?: string;
}

/** Consumer-owned: who can participate. Pure over data loaded at startup; no I/O. */
export interface Participants {
  list(): readonly ParticipantSummary[];
  /** Plan rooted at an available participant ID; throws an actionable error otherwise. */
  plan(root: string): WorkPlan;
}

Core validates the root and identity map; no YAML, skill IDs, sandbox images or delegate graph appears here. The generic port can be implemented by an in-memory fixture or any application source.

Interface: where work runs

export interface WorkInstance {
  readonly workId: TaskId;
  readonly conversationId: ConversationId;
}
export interface WorkEnvironmentRuntime extends Pick<
  Harness,
  "commit" | "snapshot"
> {}

/** Consumer-owned: where participants run. Every method is idempotent and safe after restart. */
export interface WorkEnvironment {
  /** Working directory given to participants inside the environment. */
  readonly cwd: string;
  ensure(
    work: WorkInstance,
    runtime: WorkEnvironmentRuntime,
    context: Context,
  ): Promise<void>;
  release(work: WorkInstance, runtime: WorkEnvironmentRuntime): Promise<void>;
  /** Remove resources no longer backing one of the given live works. */
  reconcile(
    live: readonly WorkInstance[],
    runtime: WorkEnvironmentRuntime,
  ): Promise<void>;
  executionEnvironment(
    target: EnvTarget,
    context: Context,
  ): Promise<ExecutionEnv | undefined>;
}

The optional SandboxWorkEnvironment persists its own resource identity. Native env routing uses that identity, never the current catalog. Capacity remains a core admission count, not a racy Docker availability reading.

Interface: agent and directory modules

directorySource(alias, root): DefinitionSource
DefinitionSource.snapshot(manifestName): Promise<{
  packages: readonly DefinitionPackage[];
  diagnostics: readonly Diagnostic[];
}>

parseAgent(markdown, sourceAlias, location): AgentDefinition
parseAgents(packages): { agents, diagnostics }
resolveAgentSetup(agent, defaults, skills?): ConversationSetup
agentParticipants({ agents, defaults, skills?, tools? }): Participants

These modules are optional and do not provision environments. A definition may remain discoverable while unavailable for activation. External filesystem roots and custom sources satisfy the same interface; no Git source or installer is required.

Interface: skills remain independent

loadSkills(packages): Promise<{ catalog: SkillCatalog; diagnostics }>
SkillCatalog.list(): SkillSummary[]
SkillCatalog.bind(references): BoundSkill[]
skillBinder(catalog): { tools: readonly string[]; bind(ids): Binding }
skillsExtension(): KaenoExtension

readBinding(read, conversationId, owner, context): Promise<Binding | undefined>

The native skill reader is catalog-free: saved bindings carry assigned documents and assets inline in SQLite. It can replay a pending CHAT without an agent factory, WORK or original skill source. Text references use bounded relative paths; binary assets are retrievable as base64. There is no implicit mount into a sandbox.

Tradeoffs and honest limits

Choice Benefit Accepted cost
All available participants frozen together Recovered children retain original setup and assignments. Larger saved payload; new definitions apply only to new roots after restart.
Inline binding content No external content store/GC/backup coordination. Skills increase SQLite size; package and bound-content limits apply.
Explicit selections No ambient coding or protocol tools when tools is empty. Explicit lists must include the tools a skill needs.
Directory-only first milestone Local and external sources without an installer or Git coupling. Git/HTTP source adapters remain future work.
Trusted native extensions Native sections/tasks/wrappers retain their full capability. This is not malicious-plugin isolation; Docker still has network egress.

Encoded constraints and verification

  • Mandatory metadata, known-field validation, inert unknown metadata; duplicate identities are not silently chosen.
  • No symlink packages or manifest traversal. Source files and skill trees have bounds.
  • Exact empty tool selection, including messaging and delegation tools.
  • All-to-all delegation within the saved participant plan, original depth bound and transactional host-wide capacity.
  • Selected tool removal and invalid saved binding versions fail before resume.
  • Core-only parent/child integration test; catalog-free skill replay; home/project file composition tests; actual CLI startup; real Docker work smoke test.

Use npm run verify. Existing databases need deliberate draining/migration: WORK is version 3, not a silent reinterpretation of old blueprints.

Rollout and next boundaries

  1. Put your assistant in ~/.kaeno/agent.md (or an explicit project .kaeno override).
  2. Add workers and skills in the confirmed home/project .agents directories. Restart to reload.
  3. Use a fresh database, or drain old work and back up before a deliberate migration.
  4. Choose which tools are actually exposed; no directory file installs native code or credentials.

Later work: project checkout, durable code output before sandbox cleanup, and a constrained GitHub App publisher. Those must stay separate from this definition/discovery base.

Earlier arena reviews favored native conversation plans, separate participant/environment ports, binding data rather than admission callbacks, and explicit tool selection. The final user decision removed delegate graphs and fixed the directory conventions shown here.
