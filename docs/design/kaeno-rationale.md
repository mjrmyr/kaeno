# Rationale: native jobs behind a small custom Pi TUI

The [running shape](minimal-kaeno.md) is one local process, one Pi Durable Harness and one SQLite store. `src/contact.ts` owns model setup, Harness lifetime and projections. `src/jobs.ts` owns tool-task dedup, capacity policy, native background jobs and result cards. `src/tui.ts` owns keyboard/display only. The UI is made from `@earendil-works/pi-tui` components, not Pi's stock coding-agent screen. There is no browser, remote worker or ordinary Pi `AgentSession`.

**Foundational thinking:** native Job ownership matches the local process boundary; each assignment owns a fresh child conversation, avoiding persistent specialist leases. **Idempotency:** replay reuses origin task, child-work request and root-notice request IDs; no automatic changed-ID retries. **Boundary discipline:** profiles are validated at boot, read calls reject private state and paths outside approved workspaces, and untrusted transcript bytes are stripped before TUI rendering. **Laziness protocol:** committed-state polling and a small trusted JSON directory avoid another event bus, UI framework or agent store.

The [native arena](native-arena/synthesis.md) established the choice over persistent named specialist conversations; its five [primitive probes](native-arena/verification.md) are evidence for native semantics, not substitutes for the new application tests. The [host arena](host-arena/synthesis.md) is historical: do not implement stock Pi frontend extraction, k3s pods or worker-owned stores. The older [`kaeno.sketch.ts`](kaeno.sketch.ts) is superseded by the current code.

**Tradeoffs and open verification:** a workspace is not a sandbox; `read` is restricted by path but the local process has full user permissions. Keys live in a mode-0600 plaintext file, not an OS credential vault. A fixed local loopback binding prevents two Kaeno processes from opening concurrently, not arbitrary SQLite writers or remote hosts. Notice admission is not human delivery. The local integration suite passes with an injected scripted model, but the real OpenAI provider, crash during an in-flight request, and power-loss recovery have not been proven end to end.
