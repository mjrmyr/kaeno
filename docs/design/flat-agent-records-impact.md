## Current runtime trace

1. `src/host/composition/configuration.ts` parses owner config. Today every omitted repository path becomes `""`; repo IDs are lowercased, refs retain case, duplicate aliases and conflicting same-repo refs are rejected. Local directories resolve relative to the config file. Qualified selections are strings such as `mjrmyr/myriad:swe`.
2. `src/host/composition/environment.ts` calls `withDefinitionSources`, then `packagesFrom(..., "AGENT.md")` and `packagesFrom(..., "SKILL.md")`. Snapshot diagnostics flow into catalog diagnostics; selecting an invalid/missing agent fails. A selected worker is not silently omitted.
3. `src/extensions/definitions/repositories.ts` captures full bounded immutable trees, serializes publication with `proper-lockfile`, and constructs source views. Repository views recursively search the configured subtree for exact manifests, including a root manifest; local views delegate to immediate-subdirectory discovery. Overlapping same-kind repository packages fail. A repository in both lists shares one fetched commit/export. Current recipe and manifest versions are hardcoded to 1.
4. `src/extensions/definitions/directory.ts` defines `DefinitionPackage { source, directory, manifest, origin? }` and `DefinitionSource.snapshot(manifestName)`. Local discovery checks each immediate package directory, not direct Markdown files. `readManifestFile` uses `lstat` then `readFile`; immutable host capture is important and this helper alone is not a complete race-proof no-follow boundary.
5. `src/extensions/definitions/manifest.ts` parses YAML as JSON-only data with no aliases/custom tags or duplicate keys, then validates trimmed name/description. `src/extensions/agents/agents.ts` derives `${source}:${name}`, constructs diagnostic paths by appending `AGENT.md`, validates known optional fields, preserves unknown metadata and removes duplicate identities. It does **not** enforce directory/name agreement today.
6. Agent resolution combines prompt, selected/default model, exact tools and one skills binding plus origin/native bindings. Worker IDs come from selected definitions; skills cannot grant tools. `src/extensions/definitions/origin.ts` stores catalog-free audit provenance. Core receives resolved setups; admitted WORK persists the plan and concrete knowledge rather than reading current sources for children.

An unscoped recursive search today could interpret an `AGENT.md` anywhere in a skill subtree as an agent. The new root/kind boundary must eliminate this rather than replace the search with recursive `*.md`.

## Independent collaboration and synthesis

- **Worker #5721, authoritative-docs/Myriad reviewer:** verified official sources, inventoried both production profiles, and compared strict records against a temporary dual-reader. Recommended strict flat-only, explicitly warning that Anthropic does not require filename equality and supports recursive directories.
- **Worker #5738, loader/lifecycle/homelab reviewer:** independently traced source/caching/identity boundaries and challenged the source representation, migration diagnostics, safe-path handling and cutover assumptions.
- **Lead:** traced current Kaeno sources/tests, independently retrieved official documentation, inspected Myriad/homelab main, compared whole-shape alternatives and authored the proposal/acceptance contract.

Synthesis uses strict candidate A: separate record source rather than fake package directories, exact roots rather than broad recursive Markdown, unchanged domain IDs and skills, recipe-policy separation, paired pinned release and explicit rollback. Candidate B contributes legacy diagnostics and phased verification, not permanent loading precedence. The design is screened against split ownership, two ways to load agents, shallow staging APIs and hand-synced validation. No claim of cross-model consensus: both delegates used the available general SWE agent.
